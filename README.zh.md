# 团队开关置顶（dsh-team-switch-place）

把输入框模型菜单里的「启用智能体团队协作」挪到**第一行**——排在「模型」「推理等级」之上。

默认情况下，DSH 的模型菜单自己渲染「模型」和「推理等级」两行，团队开关是通过 `conversation.input.model.options` 插槽追加的，所以永远排在第三位——正好是菜单最靠近指针的位置，手一滑就会打开团队模式。这个插件在浏览器里把那一行提到最前，其余行为一律不动：开关还是同一个开关，状态还是同一个状态。

- **不花 token**：宿主侧是空的，不注册工具、不注入提示词、不产生任何模型请求。
- **不认语言**：靠结构识别（菜单里唯一带 `role="switch"` 的那一行），中文、英文、日文界面都一样。
- **不改官方文件**：不 patch、不 fork、不覆盖任何官方包。
- **可回退**：禁用或卸载插件后，那一行回到原来的第三位；菜单重新打开时会自动重新应用。

## 安装

```sh
dsh plugin --profile web add dsh-team-switch-place
```

桌面端也可以在 **插件 → 添加插件** 里填包名安装，或者用本地目录路径（开发时）：

```sh
dsh plugin --profile <你的 profile> add "C:\path\to\dsh-team-switch-place"
```

安装后刷新页面（`Ctrl+Shift+R`）。页面的启动清单在每次加载时生成，所以新装的客户端插件刷新就能带上；万一没出现，重启一次 DSH 再刷新。

## 用法

没有开关要开，装好即生效：点开输入框右下角的模型位，菜单第一行就是「启用智能体团队协作」。

键盘上分两条路：`Tab` 会**跳过**开关，直接落到最下面那行「推理等级」——想调档位不用先跨过开关；模型没有公布推理档位时，`Tab` 落在「模型」行。`↑`/`↓` 按视觉顺序走，第一格才是团队开关。

## 已知边界

- 只作用于 **composer 的模型菜单**（根会话）。`/model` 弹窗、子会话、以及菜单里下钻后的模型/推理列表都不受影响。
- 依赖官方菜单的 DOM 结构（`role="menu"` 里带 `role="menuitem"` 的行 + `role="switch"` 的开关）。官方大改版后可能需要适配；识别失败时插件**什么也不做**，界面保持原样，不会白屏。
- `Tab` 那条是刻意改写官方焦点顺序：官方原本把 `Tab` 交给「第一行」，提行后第一行就是开关。改写只在「菜单打开 + 焦点在触发器 + 按的是 `Tab`」时生效，识别不到触发器就退回官方行为。
- 提的是菜单里**第一个**带开关的行。将来若有别的插件也往这个菜单塞开关，只会提它找到的那一个。
- 官方把开关搬出菜单（例如搬去插件页）时，本插件自动失效。

## 开发

```sh
node --check client.js       # 语法
node simulate.mjs      # 最小 DOM 跑一遍提行、回退、Tab 与卸载
```

- `client.js`：浏览器半，`MutationObserver` 盯着菜单挂载，把团队那一行提到容器首位。
- `index.js`：宿主半，空的 `apply()`。
- `tools/asar.mjs`：本机开发用的只读脚本，从 DSH 安装目录的 `app.asar` 里取官方包源码做结构参考；已加入 `.gitignore`，不随仓库和 npm 包发布。
